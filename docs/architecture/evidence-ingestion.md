# Evidence ingestion

A dedicated one_ingest role can insert evidence and invoke a narrow collector assignment resolver. The server-only ingestion factory verifies tokens using a trusted verifier configured for a dedicated collector audience, resolves enabled collector and host plus authoritative project assignments, locks those rows during normalization and insert, and rejects duplicate submission IDs per collector/project. No public HTTP endpoint is enabled. The privileged resolver requires migration-owner review; the trusted ingestion process is a security boundary, not an untrusted database client. Submission IDs prevent exact ID reuse, not replay with a new ID. Collector assertions are not independent proof of host state. Resource lifecycle, signed observation provenance, rate limits, retention and production credentials remain pending.
