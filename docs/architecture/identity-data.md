# Database-backed identity resolution

A separate one_identity NOLOGIN group role receives only schema usage and execute on the narrow resolve_membership function. A trusted server pool using a dedicated login invokes the function after cryptographic verification; never expose it directly to clients. The function is SECURITY DEFINER with fixed search path and requires a trusted migration owner capable of reading forced-RLS membership rows (CI uses postgres). Production ownership and privilege review are required. The ordinary one_service role is not granted lookup access. No direct identity table access is granted. The transaction boundary still rechecks and locks membership. Existing membership foreign keys mean removal of historical actors requires a future explicit revocation model. No production credentials configured.
