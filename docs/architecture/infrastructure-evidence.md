# Infrastructure evidence normalization

Trusted server configuration supplies host identity and explicit resource ownership assignments. The normalizer projects Docker inventory into project-scoped records, excludes unassigned and ambiguous resources, strips unverified cross-resource links, distinguishes stale cached observations from unavailable collection, and hashes canonical evidence. Hashes are integrity checks, not proof of origin. No client-supplied ownership mapping is permitted. Host identifiers and assignment lifecycle require authoritative persistence before deployment. This is a pure normalization boundary, not an ingestion endpoint or database writer. Next: restricted collector identity, authoritative ownership registry, append-only evidence persistence, replay controls and tenant-scoped retrieval. Docker names may contain sensitive information; production disclosure review is required.
